Commercial hardware available today: Samsung CMM-D up to 512 GB per module and CMM-B up to 16 TB per box; XConn Apollo 256-lane CXL switch with MemVerge GISMO pool demos; Astera Labs Leo smart memory controller; Marvell Structera near-memory compute. Software: vLLM with PagedAttention, the allocation and paging baseline every offload layer sits on; LMCache, now a first-class cross-tier KV layer doing pinning, lookup, compression, batched movement, compute and I/O pipelining, cross-engine transfer and prefill-decode disaggregation; SGLang with RadixAttention; NVIDIA Dynamo; Mooncake; FlexGen; InfiniGen; LayerKV; KVPR. TraCT does rack-scale KV sharing and transfer over CXL on NVIDIA Dynamo, with direct GPU-to-CXL operations behind a rack-wide prefix-aware cache — CXL-native KV caching already ships, so this package is not the first or the only one. PNM-KV selects which KV pages are needed before paying the movement cost from a processing-near-memory accelerator behind CXL. CacheWise predicts reuse from agent and tool-call state. Tutti removes the CPU from the GPU-to-NVMe KV I/O path. Research this package builds on rather than competes with: H2O, SnapKV, Scissorhands, PyramidKV, Quest, Ada-KV, HeadKV, InfiniGen, LayerKV, KVPR, PagedAttention. What remains open is a unification, not an implementation: whether one KV-State Control Plane — SELECT, PLACE, MOVE, ATTEND, OBSERVE — should decide relevance, reuse, residency and movement jointly rather than leaving each to a separate subsystem. Nobody has built or tested that, this package included. Its one empirical result sits inside PLACE and is simulated and provisional: letting identity-keyed policy state survive HBM eviction is worth plus 34.15 percentage points to LFU, from 15.56 to 49.71 percent, and plus 24.85 to EMA alpha 0.01, from 31.54 to 56.39 percent, at a 32 gibibyte budget, while EMA alpha 0.15 is unchanged at minus 0.21 percentage points — larger than the spread between policies, and a protocol result testable with no CXL hardware. Retracted from this figure: 640 per-head eviction queues, because every head of every layer is required for every token and evicting a head produces wrong outputs rather than a cache miss, so the unit is a (sequence, token block) of 16 tokens, 5.00 mebibytes, and per-head signals are used only for scoring; alpha = 0.2, never validated, with a simulated optimum near 0.05 and non-monotonic behaviour and no convergence onto LFU as alpha approaches zero; the RoPE prefetch window, because RoPE is a rotation applied to Q and K at compute time and carries no information about which blocks are needed next; and the 97 percent hit rate and 16 times user capacity behind the old opportunity framing. The scoring function is not novel: a decayed-frequency score is LRFU, Lee et al., ACM SIGMETRICS 1999, with alpha its documented LRU-to-LFU knob. No CXL hardware was measured. Research we build on Academic Papers
PNM-KV
arXiv:2511.00321 — November 2025
Paper
CXL + processing-near-memory 1M tokens Steady-token selection
Offloads token page selection to a PNM accelerator behind CXL — the closest published work to putting KV-cache decisions on the memory device.
What it optimises: Selecting which KV/token pages are needed before paying the movement cost — conceptually adjacent to the SELECT stage of this package's control plane, not a cruder version of it.
H2O · SnapKV · Scissorhands · PyramidKV · Quest
H2O: arXiv:2306.14048 (2023)
Paper
Attention-score eviction Heavy hitters Query-aware selection
Attention-score-based KV eviction and selection is established prior art. This document does not claim to have invented it.
What they evict: (head, token) pairs — the token axis is not optional. A head alone is never an eviction unit: dropping one gives wrong outputs, not a cache miss. Token dropping is a lossy relaxation with an accuracy-evaluation burden.
Ada-KV · HeadKV
Ada-KV: arXiv:2407.11550 (2024)
Paper
Per-head budgets Head-type awareness Retrieval/induction heads
Allocating a different cache budget per attention head is likewise established prior art, and is the direct antecedent of the per-head tracking used here.
What they optimise: Per-head cache budgets on the GPU. This package reads the same per-head signal but aggregates it into one score per (sequence, token block) — scoring granularity, never eviction granularity.
🗺 Where Cache Policy Lives Today
In the serving framework
vLLM/PagedAttention, SGLang/RadixAttention, Dynamo, LMCache (a first-class cross-tier KV layer), CacheWise (reuse prediction from tool-call state), Tutti (GPU-direct NVMe movement).
In the model runtime
H2O, SnapKV, Scissorhands, PyramidKV, Quest, Ada-KV, HeadKV: attention-score eviction over (head, token) pairs and per-head budgets, on the GPU. Real results this package builds on.
On the host CPU
FlexGen, InfiniGen, LayerKV, KVPR, Mooncake: offload and speculative fetch driven by host software over a driver-mediated PCIe path.
On the CXL device
Astera Leo, Marvell Structera, Samsung CMM, and TraCT — a rack-scale, prefix-aware CXL KV cache on Dynamo doing direct GPU↔CXL operations. CXL-native KV caching already ships.
What is genuinely open — a unification, not an implementation
Every layer above already solves a real, non-trivial sub-problem. What none of them does is decide relevance, reuse, residency and movement jointly. That is the open question this package is oriented around — a KV-State Control Plane over SELECT → PLACE → MOVE → ATTEND → OBSERVE — and nobody has built or tested it, this package included. Its one empirical result lives inside PLACE: identity-keyed policy state surviving HBM eviction, worth +34.15 pts to LFU (15.56 → 49.71) and +24.85 pts to EMA α=0.01 (31.54 → 56.39) at 32 GiB, with EMA α=0.15 unchanged (−0.21 pts). A protocol result, testable with no CXL hardware. Treating it as validation of the whole pipeline would be a significant overclaim. Simulated (provisional)
🔬 The KV-State Control Plane — where this package fits, and where it does not
SELECT — Design / unvalidated
Which regions or blocks are worth considering. Past-only signals (recency, frequency, LRFU decay) and predictive ones (agent/tool state, prefix identity, reuse history) — the slot CacheWise and PNM-KV occupy. Not built here.
PLACE — Simulated (provisional)
Which tier a block occupies, and whether its identity-keyed policy state crosses with it. +34.15 pts to LFU · +24.85 pts to EMA α=0.01 at 32 GiB. The only box with evidence. Unit: (sequence, token block), 16 tokens = 5.00 MiB — never a head.
MOVE — Design / unvalidated
Scheduling, batching, hiding movement behind compute. No CXL hardware measured: a 5.00 MiB block is 164 / 82 / 43 µs at an assumed 32 / 64 / 121 GB/s, against 9 / 11 / 18 ms to regenerate 16 tokens at 50 / 40 / 25% MFU.
ATTEND · OBSERVE — Design / unvalidated
The model consumes the placed state; what was attended feeds the next SELECT. Conceptual only. Scoring throughout is LRFU (Lee et al., ACM SIGMETRICS 1999) — prior art, α its documented LRU↔LFU knob; α = 0.2 was never validated.
